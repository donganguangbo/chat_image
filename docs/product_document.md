# 产品需求文档 (PRD)：本地高自由度(Uncensored)视觉生成测试平台

> **应用场景**: 针对高频、高拟真度的大尺度成人/NSFW内容、或极限画质视频生成的闭门综合测试。
> **对标产品参考**: ourdream.ai (仅限其视觉生成与呈现部分，摈弃聊天互动)
> **极速体验**: 不加任何安全锁 (Unfiltered)，直接对接顶级开源模型节点。

---

## 1. 产品核心定位

**愿景**：打造一款**完全跑在本地高端显卡（RTX PRO 6000）上**、拥有**极简 Web 可视化界面**的纯净级生成模型测试控制台。

**核心痛点解决**：
1. **解除枷锁**：彻底摆脱商业 API 在生成人体极致特征（NSFW、极限视角、敏感动作）时的自动截断与封号风险。
2. **多模态合一验证**：将目前各自为战的**静物/人物高精生图**与**顶级视频动画生成**（让高质量静态人物动起来）合并到一个系统里进行连贯测试。
3. **消除部署门槛**：摒弃让非技术人员在黑框里敲命令或拖拽 ComfyUI “乱麻”般节点的复杂操作，只给最终用户暴露“输入框”和“生成按钮”。

---

## 2. 功能模块定义 (四大核心生成引擎)

Web 页面设计为极简的单页应用 (SPA)，主视口分为 **四大生成专区 (Tabs)** 与一个 **本地画廊库 (Gallery)**。

### 2.1 模块一：文生图 (Text-to-Image / T2I)
*   **功能描述**：输入纯文字描述，输出极致逼真的静态大图。
*   **核心控件**：
    *   正向/反向提示词输入框 (Prompt / Negative Prompt)。
    *   长宽比例快速选择 (1024x1024, 16:9, 9:16)。
    *   生成按钮。
*   **底层支撑**：`FLUX.1 [dev]` 搭配高分去审查 LoRA，负责产出类似真实数码相机的极品图像。

### 2.2 模块二：图片编辑 (Image Editing / Inpainting)
*   **功能描述**：用于修改已有图片的局部细节（如脱衣、换装、替换某个极其特殊的身体部位等）。
*   **核心控件**：
    *   底图上传区。
    *   画布遮罩涂抹 (Mask Brush) 工具：用户将需要重绘的区域涂黑。
    *   重绘指令输入框 (例如：`change to transparent lingerie`)。
    *   融合度调节滑块 (Denoising Strength)。
*   **底层支撑**：`FLUX.1 Inpainting` 专精模型。

### 2.3 模块三：文生视频 (Text-to-Video / T2V)
*   **功能描述**：直接通过文字描述一段连续的动态画面。
*   **核心控件**：
    *   带有时间轴预期的长文本提示输入框。
    *   时长/帧率选项（受限于显存，目前设定为约 3-5秒的高清片段）。
*   **底层支撑**：`Wan 2.2 14B V2V` 模型（阿里绝版高质模型）。

### 2.4 模块四：图生视频 (Image-to-Video / I2V) —— **最核心战力**
*   **功能描述**：ourdcamer 级别体验的灵魂。用户先在模块一生成了一张极致诱惑/完美的静止 NSFW 人物图片，将其拖入此模块，加入动作指令，让角色顺滑地“动起来”而不崩坏骨架。
*   **核心控件**：
    *   高精首帧上传/拖拽落库区。
    *   动作镜头指令框 (Camera/Subject Action Prompt)。
*   **底层支撑**：`Wan 2.2 Image-to-Video` 模型。

## 3. UI/UX 体验流设计

*   **视觉风格**：极夜黑 (Midnight Dark) 为主色调，界面无冗余装饰。所有的注意力都聚焦于中心的画布与右侧的操控面板。
*   **生成等待反馈 (UX Padding)**：
    *   由于 RTX PRO 6000 跑 14B 视频模型需要近几分钟。点击生成后，界面绝不能卡死。
    *   **排队机制**：UI 顶部需展现一个轻量级的 `Task Queue (任务队列)`，显示当前引擎正在渲染的百分比。用户可以切走去看之前生成的作品。
*   **图片/视频持久化**：
    *   所有的产出不能仅仅保留在浏览器内存里，需后台写入特定的本地物理文件夹 (`/outputs/images/`, `/outputs/videos/`) 并能按照时间线展现在前端 Gallery 组件中。

## 4. 技术栈实施规范

为了达成最轻量化、最稳定、最低系统消耗的目的：

1. **引擎层 (Core AI GPU Engine)**：
    *   **ComfyUI**：通过 `--listen` 启动，作为纯粹的隐匿后端。其优势是极高效率的内存管理与预缓存能力。
2. **中间网关服务 (Backend API Layer)**：
    *   **技术选型**：`Python FastAPI` 或 `Node.js (Express)` 均可（极其轻量）。
    *   **核心职责**：接管 Web 的 HTTP 请求，将其翻译组装为目标模型的 JSON Workflow，并通过 WebSocket 持久化监听 ComfyUI 发回的渲染百分比，再将其转发给 Web 页面。
3. **操作台前端层 (Frontend UI)**：
    *   **技术选型**：如果考虑极简部署，直接采用 `Next.js (React)` 编写出静态大包，或 `Vue 3`，只需起一个开发服即可运行在宿主机上。

## 5. 项目落地关键节点 (Roadmap)

1. **里程碑 1 (M1)：底层 API 贯通**。
   * 配置好了 ComfyUI 和显卡驱动，成功拉取了 FLUX 和 Wan 2.2 模型。
   * 手工编写的 Python 脚本通过 ComfyUI JSON 接口生成了任意两张不同维度的 NSFW 照片。
   
2. **里程碑 2 (M2)：中台服务网关建设**。
   * FastAPI 服务器可被外部调用，封装了文生图接口、图生视频接口。能上传底图至暂存区。
   
3. **里程碑 3 (M3)：Web UI 完成与联调**。
   * “深色测试站”网页可无缝发请求、显示进度条、播放生成的视频。业务闭环完成。
